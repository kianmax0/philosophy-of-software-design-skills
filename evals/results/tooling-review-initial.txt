1. [P1] Blind task export leaks grading intent through the case ID — scripts/prepare_eval.py:20-23; evals/cases.json:39-45, 297-306
`prepare_case` includes `case["id"]` in the payload sent to the fresh agent. The case IDs are semantic labels such as `absence-is-not-failure` and `fix-optional-setting-failure-contract`; they disclose the expected diagnosis/change before grading. The request often states the subject, but the ID adds an answer-shaped cue (and the review-only case's request does not itself name the specific masking bug). Export an opaque run identifier or omit the corpus ID from the agent-facing payload, and keep the mapping in the evaluator's private record. Add a test asserting that exported task metadata does not expose criterion-bearing names.

2. [P2] Validator crashes instead of reporting malformed `mode` values — scripts/validate.py:166-167
`case.get("mode") not in {"review", "implementation"}` raises `TypeError` for valid JSON values that are unhashable, such as `[]` or `{}`. Since this function is the corpus validator and already reports schema errors, malformed corpus input should return an error rather than abort validation. Check that mode is a string before set membership and cover list/object modes in the malformed-schema tests.

3. [P2] Retained implementation check makes a false claim about kind validation — evals/results/implementations/centralize-versioned-record-construction/check_contract.py:50-60; evals/results/verify_implementations.py:56-78
The comment says the storage boundary rejects malformed records “including an unknown kind,” but the examples only reject an old schema version and a string timestamp. More importantly, the independent replay test explicitly treats `kind: "other"` as accepted legacy behavior, and the implementation's validator also accepts it. This contradiction misstates the contract and makes the retained check misleading. Align the comment with the compatibility contract (unknown kinds accepted), or change both implementation expectations only if rejecting them is actually intended.
